Agent Tool Router

Latency-aware router that picks between 7 specialist tools for an internal copilot. Cut p95 latency by 41% vs. a baseline ReAct loop, with no measurable loss of task success.

2025 · LangGraph, OpenTelemetry, Modal · summary published with employer approval

The setup

The copilot fronted 7 internal tools: codebase search, runbook lookup, log query, deployment status, ticket creation, alert correlation, and a fallback general-knowledge call. A naive ReAct loop with all 7 tools advertised at once was making 2–4 tool calls per user query, most of them unnecessary.

What changed

  • A tiny classifier (DistilBERT, fine-tuned on 4k labeled queries) routes each query to a shortlist of likely-relevant tools before the agent loop starts. Median shortlist size: 2.
  • Tools have annotated cost profiles (median latency, error rate, blast radius). The agent prefers cheaper tools when their predicted utility is within a small margin of the expensive one.
  • OpenTelemetry traces every decision; we can reconstruct why the agent picked tool A over tool B for any historical request.

What we measured

  • p50 latency: −27%.
  • p95 latency: −41%.
  • Task success on the held-out eval set: −0.4% (within noise).
  • Token spend: −33% (this was the unexpected bonus).

What surprised me

The classifier didn't need to be perfect. Even at 78% top-1 accuracy, having the right tool in the top-2 shortlist 96% of the time was enough — the agent could pick correctly from a small set, but struggled when given everything. The lesson generalizes: constraining the action space is often a bigger win than improving the policy.
